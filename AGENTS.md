# Response style

Every answer is exactly 3 short bullet points, plain language, no technical jargon (no file paths, line numbers, function/variable names) unless the user explicitly asks to go deeper. Lead with what matters most and make it engaging — not a dry log. Nothing before the bullets, nothing after. Expand only if asked.

# notes/

`notes/` holds Josh's personal design notes and prompt drafts (historical). It is not
documentation and not authoritative — the code and its live prompt constants always are. Don't
cite anything in `notes/` as current behavior without checking it against the real source first.
